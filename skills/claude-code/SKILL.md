# Issues in Obsidian

Issues are Markdown notes inside project folders of an Obsidian vault. Each project folder holds a project note and an `AGENTS.md` written by the Issues plugin. Everything is done by reading and writing files; Obsidian picks up changes on its own.

## Configuration

Edit this block once per machine. Everything else is discovered.

```yaml
roots:
  - /path/to/vault/Projects
```

`roots` lists the folders that contain project folders. Add a line for every vault or area that holds projects.

## Find the project

Do this at the start of any issue-related request; never rely on a remembered list.

```bash
for root in /path/to/vault/Projects; do
  grep -l -E '^type: project$' "$root"/*/*.md 2>/dev/null
done
```

Each hit is a project note. Its folder is the project folder; the `project:` line in its frontmatter is the key, for example `BRE`. Resolve what the user names by key (`BRE`), by folder name (`Breathe`), or by a close match of either, case-insensitively. When two projects could match, ask.

## Follow the project's AGENTS.md

`<project folder>/AGENTS.md` is generated by the plugin from that project's configuration and is the complete contract for working with its issues: where the files are, what to write, how statuses and releases work, what breaks the list. Read it before any read or write and follow it to the letter. Nothing in this skill overrides it.

If the file is missing, the project has never been opened in Obsidian with the plugin enabled. Ask the user to open the project note once, which writes the file, rather than guessing the rules.

## Working style

- Keep what you write short: a title that fits in one line and a body of a paragraph or two from what the user said.
- When a request leaves the project, status or type open, ask with the choices you discovered rather than guessing.
- After creating or changing an issue, reply with its key and path.
- When an issue key comes up in conversation, open the note and use its title, status and body as context before answering.
- In a code repository for that project, use the issue key in commit messages and branch names.
- Do not open or drive Obsidian; file edits are enough and reach other devices through the vault's sync.
